# 05 验证门禁与证据

## 四道门（全绿才可交付用户）
| 门 | 内容 | 证据形态 |
|---|---|---|
| G1 编译 | Unity batchmode 构建 0 error | 构建日志路径 |
| G2 源码验收 | Reviewer 直读改动，核对 @trace | 审计报告（file:line 级） |
| G3 产物验收 | 录屏/截图逐帧核对（STG 教训：帧序列能抓出方块弹、隐身敌机） | 帧索引+截图 |
| G4 AI 验证门 | Agnes 真玩 + QA 评审放行 | play log + QA 结论 |

## 硬规则
- "已修复"必须有对应可观察证据（STG 翻车教训：说了清场却漏飞船、漏能量球）
- 清场类/池化类改动必须列全清单逐项核对（子弹/敌人/飞船/球/塔/舰队/特效）
- 数值改动必须附极值验算（银橙规范：公式可复算，写变量、单位、取值范围）
- 构建后必须验证产物时间戳与符号（robocopy 可能静默不同步——用 cp 并校验）
